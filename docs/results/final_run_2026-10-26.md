# Final runs, 26 Oct 2026 (Brev L40, Qwen3-8B via vLLM, test split = 1159 episodes per version)

**Suite:** these runs used the test suite from before PR #25 (1159 episodes per version; `suite_manifest_pre25.json` sha256 `fe37f16c7e5701bb…`; `suite_manifest.json` now describes the #25 suite). #25 grows the test split to 2299 per version, so don't compare row counts across the two suites.

Headline config: **base memshield (Ahan's DeBERTa-v3-base) + DeBERTa-v3-large NLI** (`MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli`), ProtectAI prompt screen. `docs/results.md` is generated from `results/attacks/final-base` (latency from `final-base-latency`, 1 worker, 5 episodes per family).

## Test split, version `full`

| | base memshield (headline) | stabilised memshield-large (seed 16) |
|---|---|---|
| oracle attack success | 32/819 = 3.9% [2.8, 5.5] | 26/819 = 3.2% [2.2, 4.6] |
| hijacked actions | 0/363 | 0/363 |

| added write / read ms (1 worker) | +25.1 / +0.9 | not measured |

- **Choice:** the two memshield models are within each other's intervals. The headline uses base memshield; picking the large one because of these test numbers would be tuning on test.
- **Large memshield alone:** in `write_checks` it lets more attacks through, 38.8% vs 32.5%, and many more **hijacked actions**: 205/363 = 56.5% vs 145/363 = 39.9% on test (dev: 63.0% vs 43.5%). `full` hides this only because the registry binding stops every hijack. It is more conservative: on memshield-bench test it gets P 1.000 / R 0.837 / F1 0.911 with 0% clean rejected, vs base P 0.936 / R 0.898 / F1 0.917 with 2.3% (`memshield_large_test_metrics.json`).
- **Harmless writes rejected:** 9.3% on 25 Oct (base NLI) → 5.2% (large NLI).

## memshield-large stabilisation (PR #22)
- **Seeds:** 5 seeds; the seed and threshold are chosen on calibration data only. Calibration = memshield validation (175) + held-out MemEvoBench dev (40) + harmless suite dev writes (149).
- **Thresholds:** 0.910 / 0.816 / 0.995 / 0.997 / 0.998. The earlier unstable run picked 0.022. No seed hit the 0.5 floor.
- **Dev gate** (large `full` rejects ≤ 5% harmless writes, accuracy within 2 points of base): passed. Large rejected 2.3%, base 2.7%; accuracy 95.7% for both.
- **The dev false-rejection figure is in-sample:** the threshold was fitted on the same 149 dev writes (Ahan's review). The test run above is the first independent false-rejection number.

## NLI model, confirmed on dev (PR #23, Aditya's review)

Version `full`, dev split, base memshield on both sides:

| | base NLI (cross-encoder) | large NLI |
|---|---|---|
| harmless writes rejected | 12/256 = 4.7% | 7/256 = 2.7% |
| attack success | 23/749 = 3.1% | 27/749 = 3.6% |
| benign task accuracy | 95.7% | 95.7% |
| added write ms (1 worker, 125 episodes) | +25.3 | +25.2 |

- **The choice was confirmed on dev**, not only on test: harmless writes rejected 4.7% → 2.7% (test: 9.3% → 5.2%) at the same latency.
- **Attack success on dev went from 23 to 27 of 749** with the large model. The intervals overlap, so it is not a significant difference, but it is not "no change".
- The large NLI model was trained on MNLI/ANLI, so those sets can't be used to calibrate it.
